# ARCHITECTURE — ScamShield BD

> How the code is organised, how data flows, and what each module promises to the others.
> Rule of thumb: **`src/` is the single source of truth. The final `notebook.ipynb` is a generated artifact.**

---

## 1. Design principles

1. **One codebase, two shells.** Develop in `src/` with scripts. The submitted notebook is *generated* from `src/` by `tools/build_notebook.py`, so what we validate is exactly what we ship.
2. **Contracts before code.** Teammate and Nabila work in parallel; the interfaces in §4 are fixed first.
3. **Leakage-safe by construction.** Folds are created once, saved to disk, and reused by every experiment.
4. **Deterministic.** One `SEED` in `config.py` feeds numpy, sklearn, torch and any sampling.
5. **Cache expensive things, but never depend on caches in the final run.** Embeddings and synthetic data are cached locally for speed; the notebook must be able to rebuild them (or contain a frozen copy, see §7).
6. **Inference works on any new text** (`predict_df`), because organisers may re-run on extra data.

## 4. Module contracts (frozen interfaces)

Keep signatures stable so both teammates can work in parallel. Changes need a note in `MEMORY.md`.

| Module | Function | Contract |
|---|---|---|
| `data_loader` | `load_sample() -> DataFrame` | columns: `id, text, label, techniques, action` (`techniques` raw string) |
| | `load_test() -> DataFrame` | columns: `id, text` |
| `preprocessing` | `build_views(df) -> DataFrame` | adds `text_raw` (unchanged), `text_norm`, `text_skel`, `n_msgs`, `first_msg`, `last_msg`, `has_url`, `noise_ratio`, `script_bangla_ratio`, `emoji_count`, … Never drops rows; never edits `id` |
| | `normalise_chars(s) -> str` | NFKC, zero-width removal, lookalike mapping (see DESIGN §2) |
| | `is_noise_token(tok) -> bool` | gibberish detector for `wkrjfejejrn`-style strings |
| `cross_validation` | `make_folds(df, n_splits, n_repeats, seed) -> dict` | writes `outputs/folds.json`: `{row_id: {repeat: fold}}` plus `group_id` per row |
| | `get_folds(df) -> list[(train_idx, val_idx)]` | reads `folds.json` |
| `augment` | `corrupt(text, rng, level) -> str` | label-preserving; `level∈{light,medium,heavy}`; operator set A for training, set B reserved for evaluation |
| | `expand(df, k, seed) -> DataFrame` | adds columns `group_id` (= source row's), `source='aug'`, `weight` |
| `features.tfidf_features` | `TfidfBlock.fit(texts_unlabeled_ok).transform(df) -> csr_matrix` | fit on train+test text is allowed (unsupervised, declared) |
| `features.embedding_features` | `embed(texts, model_name, batch, max_len) -> np.ndarray` | length-sorted batching, fp16 on GPU, disk cache keyed by (model, text hash) |
| `models.task_*` | `fit(X, y, weight, seed)`, `predict_proba(X)` | A: (n,6). B: (n,6) independent probs. C: (n,6) |
| `evaluation.metrics` | `score_all(y_true, y_pred, ...) -> dict` | `F_A, F_B, F_C, brier_cal, S_hat` and per-slice values |
| `evaluation.calibration` | `fit_confidence(oof_probs, y_true, extra_feats)`, `apply(...)` | returns confidence in [0.03, 0.97] |
| `postprocess` | `apply_rules(label, tech, action, probs) -> (label, tech, action)` | rules derived from data, see DESIGN §6 |
| `submission` | `build(ids, label, tech, action, conf) -> DataFrame` | strict 5-column format, `NONE` for no technique |
| `prediction` | `predict_df(df_text, fitted) -> DataFrame` | works on arbitrary new text, no hardcoded ids |
| | `main()` | fit on all labeled data, predict test, validate, write submission |

## 7. Notebook build pipeline

`tools/build_notebook.py` assembles `notebook.ipynb` from a manifest:

1. **Declaration cells (markdown, first):** libraries + versions/install cell; every external dataset, pretrained model and API with source and licence/provider; method and validation summary; seeds and run instructions.
2. **Install/setup code cell.**
3. **One `%%writefile src/<module>.py` cell per module** (in dependency order) so the notebook recreates the exact package, then plain `from src... import ...` cells. Dev code and shipped code cannot drift.
4. **Frozen data cells:** hand-written examples and, if used, the frozen LLM-generated set, stored compressed inside the notebook. The generation code stays in `synthetic_llm.py` and is guarded by `REGENERATE_SYNTH`.
5. **Run cells:** validation summary (grouped CV, slices, confusion), final fit, `predict_df`, validation of the file, write `submission.csv`.

`tools/make_zip.py` produces the ZIP with **exactly four items** (`submission.csv`, the notebook, `README.md`, `.env`) and fails otherwise. The ZIP name is set by one constant (see `MEMORY.md` §3 for the open naming question).

## 9. Testing and validation hooks

Fast tests (`pytest -q`, under a minute):
- `test_preprocessing.py`: idempotent, preserves `|||`, preserves Bangla chars, strips zero-width, never returns empty for non-empty input.
- `test_augment.py`: corruption keeps `|||` and length bounds; seeded determinism.
- `test_folds.py`: no group appears in both train and val; augmented rows share their source's group.
- `test_submission.py`: validator accepts a good file and rejects each bad pattern (float label, empty techniques, duplicate id, missing id, confidence > 1).
- `test_predict_df.py`: `predict_df` runs on 5 unseen strings, including an empty string, a noise-only string and a 12-message conversation.

## 10. Error handling and logging

- Empty/NaN `text` → treated as noise-only record (never raise).
- Any exception in an optional component (LLM, embeddings) falls back to Model 1 and logs a clear warning; the final run must not crash because an API is down.
- `outputs/validation_results/experiments.csv` receives one row per experiment: id, git hash, config JSON, `F_A, F_B, F_C, Brier, S_hat`, slice scores, notes.
